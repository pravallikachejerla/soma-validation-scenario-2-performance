## What the app does

- Hosts a versioned REST API under `/api/v1` for interactive
  pricing, batch pricing, promotion management and administrative
  search.
- Persists tenants, products, customers, contract prices,
  eligibility rules, promotions, conditions, requests, decisions,
  batch jobs, audit events and configuration versions.
- Provides a small React console with pages for the product list,
  promotion editor, pricing simulator, batch dashboard, decision
  explanation, audit viewer and admin search.
- Exposes Prometheus metrics and a structured JSON access log.

## Quick start

```bash
make build           # build the Go binaries
make seed            # generate testdata/fixtures/{small,medium,large}.json
make test            # run the public test suite
make up              # bring the docker compose stack up
make migrate         # apply migrations against $DATABASE_URL
curl http://localhost:8080/healthz
```

The application listens on `http://localhost:8080`. The frontend
preview listens on `http://localhost:5173`.

## How to run

| Step | Command | Notes |
|------|---------|-------|
| 1 | `go build ./...` | Compiles every binary into the local cache. |
| 2 | `go run ./cmd/seed -out testdata/fixtures -profile medium` | Writes the deterministic fixtures used by tests and demos. |
| 3 | `go run ./cmd/migrate` | Applies the SQL files under `migrations/`. |
| 4 | `go run ./cmd/api` | Starts the HTTP server on `:8080`. |
| 5 | `cd frontend && npm install && npm run dev` | Starts the Vite dev server on `:5173`. |
| 6 | `bash scripts/smoke.sh` | Exercises the public API end to end. |

For the docker compose stack, use `make up`. The compose file
brings up `db`, `migrate`, `api`, `frontend` and `seed` services and
exposes ports 8080 (API), 5173 (frontend) and 5432 (PostgreSQL).

## How to test

- `go test ./tests/public/...` runs the public engineering tests.
- `go test ./private/...` runs the private condition tests; these
  are not part of normal CI and should only be invoked by a
  reviewer with the matching expectations.
- `go test ./internal/...` runs the unit tests inside the internal
  packages.

The fixture files under `testdata/fixtures/` are deterministic and
are the only data the public tests require.

## Public API surface

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/pricing/quote` | POST | Interactive pricing. |
| `/api/v1/pricing/batch` | POST | Batch pricing. |
| `/api/v1/promotions` | GET | List promotions for a tenant. |
| `/api/v1/promotions` | POST | Create a promotion. |
| `/api/v1/promotions/{id}` | PATCH | Update an existing promotion. |
| `/api/v1/admin/search` | GET | Parameterised search over products, customers or promotions. |
| `/api/v1/admin/audit` | GET | Audit events for a tenant. |
| `/api/v1/admin/seed` | POST | Populate the in-memory store from the small fixture. |
| `/healthz` | GET | Liveness probe. |
| `/version` | GET | Build identity (commit, built_at, dataset_id). |
| `/metrics` | GET | Prometheus metrics. |

Full request/response examples live in `docs/api.md`.

## Role model

The application recognises two synthetic roles at the API edge:

- `admin` — may create, patch and search across all tenants.
- `viewer` — may only list promotions and run the simulator.

Roles are carried in the `X-Role` header. The current build treats
both roles as read-write to keep the API simple; the role-aware
navigation is exercised by the React console.

## Dataset profiles

| Profile | Tenants | Products / tenant | Customers / tenant | Promotions / tenant |
|---------|---------|-------------------|--------------------|---------------------|
| small   | 2       | 20                | 10                 | 10                  |
| medium  | 3       | 200               | 50                 | 100                 |
| large   | 10      | 1000              | 200                | 500                 |

The seeder writes `small.json`, `medium.json` and `large.json` into
`testdata/fixtures/`. Each fixture is reproducible from the fixed
seed `42` and a SHA-256 of the generated bytes is printed at the
end of the seeding run.

## Out of scope

- Real payment, taxation or shipping integration. The application
  only models money at the integer JPY level.
- Multi-region replication and global cache invalidation. The
  pricing cache is process-local.
- Authentication, authorisation and quota enforcement beyond the
  synthetic role hint. Production-grade IAM is not the point of
  this repository.
- Float-point money. Every monetary value is integer JPY.
- Customised rule languages. The promotion condition language is a
  small restricted grammar (comparisons and `&&` / `||`) and is not
  a general-purpose expression engine.
