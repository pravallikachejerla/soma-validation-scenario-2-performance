16. Proposed Controlled Branch and Pull Request

Branch: perf/candidate-a-combined-remediation

PR Title: "perf: combined remediation — N+1 fix, mutex removal, cache key isolation, batch consistency"

PR Body:

## Summary
Candidate A addresses 7 of 8 confirmed performance findings:
- F1: Remove global evalMu mutex (engine.go)
- F2: Replace N+1 LoadConditions with batched LoadAllConditions (engine.go, batch.go)
- F3: Fix compiler cache bypass (compiler.go)
- F4: Replace O(n²) resolver sort with O(n log n) stable sort (resolver.go)
- F5: Add tenant_id and config_version to cache key (pricing.go)
- F6: Fix batch rounding to match interactive (batch.go)
- F8: Add ID-based deduplication in resolver (resolver.go)

## Measured Impact (in-memory benchmark)
- Database queries: 253 → 3.52 per request (72× reduction)
- Medium-profile p95: 24–40× faster
- Medium-profile throughput: 1.1–1.7× faster

## Known Limitations
- Large-profile p95 regressed 2–3× in-memory (mutex removal exposes real per-request work)
- PostgreSQL validation not yet performed
- F7 (candidate selection scan) not addressed

## Test Plan
- All 11 regression tests pass
- All public API tests pass
- In-memory benchmark shows query-count reduction
